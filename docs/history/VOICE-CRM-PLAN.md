# תיעוד שיחות קולי → CRM מורים — מסמך תכנון לבנייה

> מסמך זה נכתב כדי שתמסור אותו כמו שהוא לקלוד שעובד על המחשב שלך. הוא כתוב בעברית עם מונחים טכניים באנגלית. אם משהו לא ברור לקלוד הבונה — שיקרא קודם את הקוד הקיים של ה‑CRM ואז ימשיך.

---

## ⚠️ הערת התאמה לפרויקט בפועל (נוסף לאחר קריאת הקוד הקיים)

המסמך המקורי נכתב סביב **Firebase/Firestore**, אבל ה‑CRM הקיים בפועל בנוי על **Supabase (Postgres)**, לא Firebase. אין שינוי בזרימה או בלוגיקה המתוארת — רק במיפוי לשכבת הנתונים:

| במסמך המקורי | בפרויקט בפועל |
|---|---|
| Firestore collection `teachers` | טבלת `contacts` (Supabase/Postgres) |
| Firestore subcollection `teachers/{id}/interactions` | טבלת `interactions` הקיימת, עם `contact_id` כ‑foreign key |
| Firebase Cloud Functions | `backend/server.js` (Express, כבר קיים; יש בו כבר `/api/google` ל‑Google Calendar tokens) |
| שדה `type` חדש ברשומת שיחה | `interactions.type` **כבר תומך** בערך `'phone_call'` — אין צורך ב‑migration לעמודה הזו |
| `transcript`, `summary`, `actionItems`, `mentionedDates`, `teacherNameSpoken`, `confirmedByUser` | ניתן לאחסן הכל בתוך `interactions.content` (טקסט) + `interactions.metadata` (JSONB) — אין צורך בעמודות חדשות בטבלה |
| הוספת PWA | ה‑frontend הוא Vite + React קיים; יש להוסיף רק Web App Manifest + Service Worker |
| Google Calendar API | תשתית קיימת חלקית — `backend/.google-tokens.json` כבר נשמר מפעם קודמת (ראה הערה על כך ב‑[CHECKPOINT-v1.md](CHECKPOINT-v1.md) לגבי אי-עמידות ב‑deploy מרוחק) |

כלומר: אין צורך ליצור collection/schema חדש — אפשר לבנות ישירות מעל `contacts` + `interactions` הקיימים.

---

## 1. מה בונים (סקירה קצרה)

הרחבה ל‑CRM המורים הקיים (React + Firebase): יכולת לתעד שיחת טלפון עם מורה **מהנייד, בקול**, והמערכת:
1. הופכת את הדיבור שלי לטקסט **על המכשיר עצמו** (הכתבה קולית מובנית — ראה סעיף 3),
2. מזהה על איזה מורה מדובר מתוך השם שאמרתי,
3. מסכמת את השיחה ומחלצת מטלות המשך,
4. מוסיפה רשומת שיחה ליומן של אותו מורה ב‑CRM,
5. ומוסיפה מטלות עם תאריך גם ליומן האישי שלך.

הכל בזרימה של: לחיצה על כפתור → דיבור → אישור בלחיצה → נשמר.

---

## 2. הזרימה מקצה לקצה (ה‑flow המלא)

1. **פתיחה** — לוחץ על אייקון האפליקציה במסך הבית של הנייד (זה PWA — ראה סעיף 3).
2. **דיבור** — מסך עם כפתור גדול אחד. לוחץ, ומדבר בחופשיות, למשל:
   *"שיחה עם רותי לוי. דיברנו על התלמידה שלה שמתקשה במתמטיקה, סיכמנו שהיא תשלח לי דוח עד יום חמישי, ואני אחזור אליה בשבוע הבא לגבי המנטור החדש."*
   הטקסט מופיע על המסך תוך כדי דיבור, בעברית, בעזרת מנוע ההכתבה של גוגל שכבר קיים במכשיר שלך.
3. **עצירה** — לוחץ שוב לעצירה. עכשיו יש טקסט מלא על המסך (אפשר גם לתקן אותו ידנית אם צריך).
4. **עיבוד** — לחיצה על "סכם". הטקסט (בלבד — אין קובץ אודיו) נשלח לקלוד (Anthropic API) שמחזיר: שם המורה שזוהה, סיכום, מטלות המשך, ותאריכים אם הוזכרו. לוקח כמה שניות.
5. **אישור** — המסך מציג כרטיס:
   - **מורה שזוהה:** רותי לוי ✓ (עם אפשרות לתקן אם זוהה לא נכון)
   - **סיכום:** 2–3 שורות
   - **מטלות המשך:** רשימה
   - כפתור **"אשר ושמור"** + אפשרות לערוך לפני השמירה.
6. **שמירה** — בלחיצה, נוצרת רשומת שיחה חדשה תחת המורה הנכון ב‑Firestore, והיא מופיעה מיד ביומן שלו ב‑CRM. בנוסף, כל מטלת המשך שהוזכר בה תאריך נוצרת אוטומטית כאירוע ביומן האישי שלך.

---

## 3. החלטות טכניות (ההמלצות שלי — כבר הוחלטו)

### אפליקציה = PWA (לא אפליקציה מהחנות)
מרחיבים את ה‑React הקיים ל‑Progressive Web App. משתמשים ב‑Web App Manifest + Service Worker כדי שאפשר יהיה "להוסיף למסך הבית".
**למה:** אותו קוד, אותו Firebase, בלי App Store / Play Store, בלי חתימות ואישורים.

### תמלול (speech‑to‑text) = הכתבה מובנית של המכשיר (Web Speech API) — השיטה הראשית
משתמשים ב‑`Web Speech API` (הממשק `SpeechRecognition`) של דפדפן Chrome, שמפעיל את **אותו מנוע הכתבה קולית של גוגל** שאתה כבר משתמש בו במקלדת. מקבעים אותו לעברית (`lang = "he-IL"`).
**למה זה הכי טוב עבורך:**
- **חינם** — הזיהוי קורה על המכשיר, בלי עלות תמלול בכלל.
- **פשוט** — אין הקלטת אודיו, אין העלאת קבצים, אין אחסון. פחות רכיבים, פחות מה שיכול להישבר.
- **מהיר** — הטקסט מופיע תוך כדי דיבור.
- אתה על **אנדרואיד + Chrome**, שזו בדיוק הסביבה שבה זה עובד מצוין.

**מגבלות שחשוב להכיר (ולכן יש fallback למטה):**
- לא אמין ב‑iPhone / Safari. (לא רלוונטי לך כרגע, רלוונטי אם תעבור לאייפון.)
- מעט פחות חסין לרעש רקע חזק מ‑Whisper. אתה מכתיב *אחרי* השיחה, אז זה בדרך כלל לא בעיה.

### חלופה (fallback) = Whisper של OpenAI
אם בעתיד תעבור לאייפון, או אם דיוק ההכתבה המובנית לא יספק (רעש, שמות שיוצאים שגויים) — אפשר להחליף את שכבת התמלול ל‑OpenAI Whisper (~$0.006 לדקה, `language: "he"`). לכן: **קלוד הבונה — בנה את שכבת התמלול כמודול נפרד עם ממשק אחיד**, כך שאפשר יהיה להחליף מ‑Web Speech ל‑Whisper בלי לגעת בשאר המערכת. במצב Whisper תידרש הקלטת אודיו + Cloud Function לתמלול; במצב הראשי אלה לא קיימים.

### סיכום + זיהוי שם + חילוץ מטלות = קלוד (Anthropic API)
הטקסט נשלח לקלוד עם prompt שמבקש להחזיר JSON מובנה: `{ teacher_name, summary, action_items[], mentioned_dates[] }`. זה גם מה שמזהה את שם המורה מתוך הדיבור החופשי.

### שרת (backend) = Firebase Cloud Functions
הקריאה ל‑Anthropic חייבת לרוץ בצד שרת ולא בדפדפן — כדי לא לחשוף את מפתח ה‑API. גם יצירת האירוע ב‑Google Calendar נעשית בצד שרת. Firebase Cloud Functions זה החיבור הטבעי כי אתם כבר על Firebase.
> הערה: בשיטה הראשית (Web Speech) **אין צורך ב‑Firebase Storage ולא במפתח OpenAI** — התמלול קורה על המכשיר, ורק הטקסט נשלח לשרת.

## 4. זיהוי המורה — הלוגיקה

1. קלוד מחזיר את השם שנאמר (למשל "רותי לוי").
2. הקוד עושה **fuzzy matching** מול רשימת המורים ב‑Firestore (התאמה גם אם יש שגיאת הכתבה קלה — למשל דמיון מחרוזות / normalization של עברית).
3. **תוצאה:**
   - התאמה ודאית → מציג "מצאתי: רותי לוי ✓" לאישור בלחיצה.
   - כמה התאמות אפשריות → מציג רשימה קצרה לבחירה.
   - אין התאמה → מציג שדה חיפוש ידני.

---

## 5. מבנה הנתונים ב‑Firestore

> קלוד הבונה: **קרא קודם את מבנה הנתונים הקיים של המורים** והתאם. להלן ההצעה, בהנחה שיש collection בשם `teachers`.

רשומת שיחה חדשה, כ‑subcollection תחת כל מורה:

```
teachers/{teacherId}/interactions/{interactionId}
{
  type: "phone_call",
  createdAt: <timestamp>,
  transcript: <string>,             // הטקסט מההכתבה הקולית
  summary: <string>,                // סיכום קצר
  actionItems: [ { text, dueDate?, done: false } ],
  mentionedDates: [ <string> ],
  source: "voice_pwa",
  teacherNameSpoken: <string>,      // מה שנאמר בפועל, לביקורת
  confirmedByUser: <boolean>
}
```

ה‑CRM הקיים צריך להציג את ה‑`interactions` האלה ביומן/בטיימליין של המורה, ממוין לפי `createdAt`.

## 6. שלבי בנייה (סדר עבודה לקלוד הבונה)

בנה בשלבים, ובדוק כל שלב לפני שממשיכים:

1. **תשתית PWA** — הוסף Web App Manifest + Service Worker ל‑React הקיים; ודא ש"הוסף למסך הבית" עובד ושהאתר על HTTPS.
2. **מסך הכתבה** — כפתור גדול שמפעיל `Web Speech API` (`SpeechRecognition`, `lang = "he-IL"`); הצגת הטקסט תוך כדי דיבור; אפשרות לתקן ידנית לפני שליחה. בנה את זה כמודול תמלול נפרד (ראה סעיף 3, כדי שאפשר יהיה להחליף ל‑Whisper בעתיד).
3. **Cloud Function לניתוח** — שולחת את הטקסט לקלוד; מחזירה JSON מובנה (שם, סיכום, מטלות, תאריכים).
4. **זיהוי מורה (fuzzy matching)** — התאמת השם מול `teachers`.
5. **מסך אישור** — הצגת המורה שזוהה + סיכום + מטלות; עריכה ואישור. בנה אותו כך שיהיה קל להפוך בעתיד לשמירה אוטומטית (flag/הגדרה אחת).
6. **כתיבה ל‑CRM + יומן** — יצירת רשומת `interaction` תחת המורה והצגתה ביומן שלו; ולכל מטלה עם תאריך — יצירת אירוע ב‑Google Calendar האישי שלך.
7. **ליטוש** — מצבי שגיאה (אין רשת, הכתבה נכשלה/ריקה, מורה לא זוהה), אינדיקציית טעינה, והרשאת מיקרופון בפעם הראשונה.

---

## 7. מה צריך להכין מראש (מפתחות והגדרות)

- **מפתח Anthropic API** (לסיכום/קלוד) — מ‑console.anthropic.com. נשמר כ‑environment config של Cloud Functions, **לא בקוד הצד‑לקוח**.
- **גישת Google Calendar API** — להוספת אירועים ליומן האישי שלך.
- אין צורך במפתח OpenAI ולא ב‑Firebase Storage בשיטה הראשית. (יידרשו רק אם תעבור בעתיד ל‑fallback של Whisper.)

---

## 8. החלטות שהוחלטו

1. **אישור מורה:** לחיצת אישור לפני כל שמירה (בשלב זה). בעתיד, כשיתברר שהזיהוי עובד טוב באופן עקבי — לעבור לשמירה אוטומטית בהתאמה ודאית.
2. **אודיו:** אין הקלטת אודיו כלל — התמלול קורה על המכשיר, ורק הטקסט נשמר. (אין קובץ אודיו לשמור או למחוק.)
3. **מטלות המשך:** מטלה שהוזכר בה תאריך נוצרת אוטומטית גם כאירוע ב‑Google Calendar האישי שלך (בנוסף להופעה ברשומת המורה). **קלוד הבונה:** ודא איתי מול איזה חשבון להתחבר.
4. **שפה:** עברית בלבד (`lang = "he-IL"` בהכתבה; `language: "he"` אם עוברים ל‑Whisper).
5. **תמלול:** השיטה הראשית היא ההכתבה המובנית של המכשיר (Web Speech API); Whisper נשמר כחלופה למקרה של מעבר לאייפון או בעיות דיוק.

---

## 9. עלות משוערת (שימוש אישי)

- **תמלול:** חינם — קורה על המכשיר (Web Speech API).
- **סיכום (קלוד):** אגורות בודדות לכל שיחה.
- **Firebase Functions:** זניח בשימוש אישי (רוב הסיכוי בתוך ה‑free tier).

בפועל: העלות היחידה כמעט היא הסיכום של קלוד — דולרים בודדים בחודש לכל היותר.
