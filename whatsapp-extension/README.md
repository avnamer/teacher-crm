# סנכרון וואטסאפ — תוסף Chrome

תוסף Manifest V3 שקורא הודעות וואטסאפ ממורים וקבוצות נבחרות מתוך WhatsApp Web
(שכבר פתוח ומחובר בדפדפן) ומתעד אותן ב-Teacher CRM. **קוראת בלבד** — לא שולחת
הודעות, לא משתמשת בשום ספרייה לא-רשמית (whatsapp-web.js / Baileys וכד'), לא
מדברת עם שרתי וואטסאפ בכלל.

## התקנה (מצב מפתח — "Load unpacked")

1. Chrome → `chrome://extensions`
2. הפעילו **"מצב מפתח" (Developer mode)** — מתג בפינה הימנית העליונה.
3. **"טעינת תוסף בארכיון" / "Load unpacked"** → בחרו את התיקייה הזו
   (`whatsapp-extension`).
4. התוסף יופיע ברשימה עם סמל 💬. אם `chrome://extensions` מציג שגיאה בטעינה,
   הפרטים המדויקים מופיעים שם — לרוב זה טעות הקלדה ב-`manifest.json`.

## הגדרה (פעם אחת)

1. לחצו על סמל התוסף בסרגל הכלים ← **"הגדרות התוסף"**.
2. **כתובת שרת ה-CRM**: כתובת ה-backend (ברירת המחדל כבר ממולאת לכתובת הייצור;
   לפיתוח מקומי יש להחליף ל-`http://localhost:3001`).
3. **טוקן חיבור**: הערך של `WHATSAPP_EXTENSION_TOKEN` מ-`backend/.env` — לא
   ממציאים אותו כאן, מקבלים אותו מאבנר (או קוראים אותו מהקובץ אם יש גישה).
4. **שמור**.

## שימוש

- פתחו לשונית עם `web.whatsapp.com` מחוברת (סרקתם את קוד ה-QR פעם אחת כרגיל).
- **סגרו את כלי הפיתוח (DevTools) על אותה לשונית לפני שמסנכרנים** — התוסף
  צריך "לתפוס" אותה בעצמו (chrome.debugger, ראו למטה) כדי שהקליקים/הגלילה
  יעבדו, וכרום מרשה רק צד אחד בכל רגע נתון. אם DevTools פתוח, הסנכרון ייכשל
  עם הודעה שאומרת את זה במפורש.
- לחצו על סמל התוסף ← **"סנכרן עכשיו"**, או על הכפתור "סנכרן וואטסאפ" בעמוד
  המורים ב-CRM (עובד גם מהטלפון — התוסף קולט את הבקשה תוך כדקה).
- בזמן סנכרון בפועל יופיע פס כתום/צהוב מעל הלשונית ("<שם התוסף> is debugging
  this browser") — זה תקין וצפוי, נעלם לבד כשהסנכרון מסתיים.
- **אין סנכרון אוטומטי יומי בשלב הזה** — רק ידני, בכוונה (ראו `docs/superpowers/specs/`
  בפרויקט העיקרי לרקע). זה יתווסף בהמשך אחרי כמה שבועות שרואים שאין בעיה בחשבון.

## למה יש הרשאת "debugger"

WhatsApp Web מתעלם מקליקים/גלילה שנשלחים באופן פרוגרמטי רגיל (JavaScript
`dispatchEvent`) — כנראה הגנה מובנית נגד אוטומציה. התוסף משתמש ב-
`chrome.debugger` (אותו מנגנון שכלים כמו Playwright/Puppeteer עובדים דרכו)
כדי לשלוח קליק/גלילה שהדפדפן מזהה כאמיתי. זה נדרש רק בזמן סנכרון פעיל, ולא
לשום מטרה אחרת.

## למה יש הרשאות "tabCapture" ו-"offscreen"

תמלול הודעות קוליות דורש לתפוס את השמע בפועל. ניסיתי לקרוא אותו דרך כל ה-API-ים
הרגילים של הדפדפן (`<audio>`, `AudioContext`, `Worker` וכד') ואף אחד מהם לא
נורה כשוואטסאפ מנגן הודעה קולית — למרות שקול אמיתי יוצא מהרמקולים. הפתרון:
`chrome.tabCapture` מקליט את מה שבפועל יוצא מהלשונית, ברמת הדפדפן, בלי קשר
לאיזה מנגנון פנימי מייצר את הקול. ה-הקלטה עצמה קורית ב-offscreen document
(`offscreen.html`/`offscreen.js`) — המקום היחיד שמאפשר לתוסף גישה ל-
`getUserMedia`/`MediaRecorder`. גם זה נדרש רק בזמן סנכרון הודעה קולית ספציפית,
ונעלם מיד אחריה.

## אם משהו לא עובד

- **"WhatsApp Web לא פתוח במחשב"** — פתחו לשונית `web.whatsapp.com` וודאו
  שהיא מחוברת (לא מציגה קוד QR).
- **"מבנה WhatsApp Web השתנה, התוסף צריך עדכון"** — וואטסאפ שינו את מבנה
  העמוד. כל הסלקטורים (מיקומי האלמנטים שהתוסף מחפש) מרוכזים בקובץ אחד:
  [`selectors.js`](selectors.js). שם צריך לעדכן.
- שגיאה על מורה ספציפי/ת ("לא נמצאה שיחה למספר של...") לא עוצרת את שאר
  הסנכרון — היא מופיעה בפירוט הסטטוס ב-CRM.

## הערת אמינות

חלק זה (בדיוק הסלקטורים מול ה-DOM האמיתי של WhatsApp Web, וההתנהגות בזמן גלילה
אחורה בהיסטוריה) **לא נבדק מול חשבון וואטסאפ חי** — נכתב לפי המבנה המתועד, אבל
כמעט בוודאות יזדקק לכוונון אחרי ריצה אמיתית ראשונה. זה הצפוי, לא סימן לבעיה
גדולה — כל מה שצריך לתקן מרוכז ב-`selectors.js` ו-`content.js`.
